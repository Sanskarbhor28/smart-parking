# Likely viva questions (with simple answers)

## Project basics
1. **What does your project do?** It records vehicles entering and leaving a car park, stores the data in a database through a cloud-style API, predicts how full the lot will be in 30/60 minutes, and shows it on a dashboard.
2. **Is the data real?** No. It is synthetic (generated by a program with realistic daily patterns). The sensors are simulated. The pipeline is real; real data or sensors can be plugged in later.
3. **Where is AI used?** Two ML tasks: predicting occupancy % (regression) and classifying demand Low/Medium/High (classification).

## Cloud computing & AWS
4. **What is cloud computing?** Using computing resources (servers, databases) over the internet on demand instead of owning them.
5. **Why is your system "cloud-based"?** Data goes over HTTP to a central API and database that can run on a cloud server; the dashboard reads from it. Locally I use SQLite; for cloud I switch `DATABASE_URL` to PostgreSQL on AWS RDS. (I designed the deployment; say honestly whether you deployed it.)
6. **What is EC2? RDS? S3?** EC2 = rentable virtual server. RDS = managed database (backups, patching). S3 = object/file storage.
7. **What is a security group?** A virtual firewall that decides which IPs and ports may reach a server.
8. **How do you control cost?** Smallest instances, stop/delete after the demo, budget alerts, no load balancers/NAT.

## FastAPI, APIs, IoT
9. **What is an API / REST?** A way for programs to talk over HTTP using URLs and methods (GET reads, POST creates).
10. **Why FastAPI?** Fast, easy, automatic validation and Swagger docs (`/docs`).
11. **What do the status codes mean in your API?** 201 created, 200 OK, 404 not found (unknown vehicle/slot), 409 conflict (lot full / already parked), 422 invalid input.
12. **What is Pydantic?** A library that validates incoming data, for example the plate must be 4-15 letters/digits.
13. **How do you simulate IoT?** `parking_simulator.py` randomly creates arrivals/departures each tick and sends them to the API, like a gate sensor would. Speed, probabilities and seed are configurable.
14. **Real sensors?** Would send the same kind of HTTP/MQTT messages; the backend does not change. Not implemented here.

## Database & PostgreSQL
15. **Explain your database.** Five tables: slots, vehicles, sessions (links a vehicle to a slot with entry/exit time), sensor_data, predictions. Foreign keys link sessions to vehicles and slots.
16. **Primary key / foreign key?** Primary key uniquely identifies a row; a foreign key points to a row in another table.
17. **Why PostgreSQL over SQLite?** PostgreSQL is a server database supporting many users and cloud hosting; SQLite is a single file, good for development. SQLAlchemy lets one code base use both.
18. **Why indexes?** They speed up searches, such as by entry time. (Note: I tested on SQLite; the PostgreSQL setup is prepared but not tested.)

## Machine learning
19. **What is Random Forest?** Many decision trees trained on random parts of the data; their answers are averaged (regression) or voted (classification). It handles non-linear patterns like rush hours.
20. **Why compare with Linear Regression and a baseline?** To check the complex model really helps. The baseline "occupancy stays the same" shows the minimum to beat.
21. **What features do you use?** Hour, day of week, weekend flag, current occupancy, occupancy 30 min ago, change, arrivals, departures.
22. **Why a time-ordered split?** Predicting the future must be tested on later data than training; a random split would leak information.
23. **What are MAE, RMSE, R²?** Average error; error that punishes large mistakes; share of variation explained. Precision/recall/F1 and the confusion matrix evaluate the classes. (Quote your own numbers from `python -m ml.evaluate`.)
24. **Is the accuracy trustworthy?** Only for synthetic data. Real data would be noisier, and results would likely be lower.
25. **Do you train on every dashboard load?** No. Training is a separate step; the API loads the saved `.joblib` model.

## Streamlit & design
26. **What is Streamlit?** A Python library to build web dashboards quickly.
27. **Why does the dashboard call the API instead of the database?** Separation of concerns and security: one gateway enforces the rules.
28. **What are the limitations?** Synthetic data, single lot, no login/HTTPS, server-time timestamps, no camera detection, cloud part untested by me.
